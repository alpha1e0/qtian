## Workflow

**请按照如下工作流进行开发**

1. **理解需求**：仔细阅读用户需求，确保完全理解需求内容和背景，必要的情况下查看`docs/specs/*.md`下面的需求设计文档了解背景，如果有不清楚的地方，及时与用户沟通确认。
2. **制定计划**：根据需求内容，制定详细的开发计划，包括需要修改或新增的模块；如果需求很大，则使用plan模式分解成多个子需求，逐个开发。
3. **确认计划**：将制定的计划与用户进行确认。
4. **执行开发**：按照确认的计划进行开发，确保代码质量和开发效率。
5. **测试**：开发完成后，进行全面的测试，包括单元测试和e2e测试（涉及到新增功能、接口，需要补充e2e测试用例）。
6. **总结修改内容**：总结本次开发的修改内容，记录到`docs/changelog.md`，以便后续追踪和回顾。
7. **询问是否git commit**：在完成开发和测试后，询问

### docs/changelog.md 格式建议

每次在文件head插入新的内容，格式如下：

```
## [当前版本号] 日期

**User**: [用户输入的需求描述]

**Summary**: 

[你总结的修改内容描述]
```

当前版本号，通过 `src\main\core\common\constants.ts` VERSION 字段获取

## 注意事项

- 对新开发的模块要编写单元测试用例，尽可能保证覆盖率
- 单元测试mock仅用于隔离外部依赖，尽量减少无意义的mock
- 开发后需要运行单元测试，并分析、改进
